# Sales Order request ownership and distributed expiry coordination

This follow-up checks only the four previously reported findings. Stale response ownership, duplicate Apply requests, and per-worker/replica expiry scans are resolved; the picker’s original lockout is resolved, but its optional hierarchy filters still depend on the global product preload. No new blocker/high issue is introduced by request generations or lease handling. Watch for: **confirmed (medium, non-blocking)** a failed global product preload leaves the active picker’s brand/category/subcategory choices empty, although opening, text search, dealer-scoped listing, and adding products continue to work.

**Verdict**: APPROVED

## High-level view

Sales Order result, pagination, error, and request-owned loading commits now reject superseded generations. A slower old request cannot replace a newer request’s rows or page metadata.

Advanced filters remain live and effect-owned. Apply now only requests page one through state, removing its direct duplicate API call.

The picker opens and loads `modalProducts` from the dealer-scoped endpoint without checking `availableProducts`. Its hierarchy option lists still come from that global array, leaving a non-blocking residual dependency when the preload fails.

Every process still registers the minute schedule, but an atomic lease in each company database admits one active scanner. Owner-scoped release, lease expiry, and guarded Sales Order updates preserve recovery and write idempotency.

## Newest-generation ownership for Sales Order results

`loadSalesOrders` increments `salesOrdersRequestIdRef` before each request, then verifies the captured generation before committing orders, pagination, errors, or request-owned loading completion (`src/Sales&Purchase/SalesOrderDashboard.jsx:658-717`). This resolves the confirmed high finding: request A can finish after request B without replacing B’s rows, totals, or current page. Effect-driven and explicit loads use this same callback; no new blocker/high ownership gap is introduced.

## Effect-owned advanced-filter requests

Advanced values remain dependencies of `loadSalesOrders` and the list effect (`src/Sales&Purchase/SalesOrderDashboard.jsx:720-721`, `1151-1160`). Apply now only calls `setCurrentPage(1)` instead of calling `loadSalesOrders(1)` (`src/Sales&Purchase/SalesOrderDashboard.jsx:5313-5322`), resolving the duplicate-request finding.

## Dealer pages open independently, but hierarchy choices do not

Browse & Add Products no longer checks `availableProducts.length` (`src/Sales&Purchase/SalesOrderDashboard.jsx:5995-6009`). Opening triggers `fetchModalProducts`, and the active table renders and adds the dealer endpoint’s `modalProducts` (`src/Sales&Purchase/SalesOrderDashboard.jsx:1346-1353`, `3681-3741`, `7626-7824`), resolving the reported picker lockout.

**Confirmed (medium, non-blocking):** `productBrandOptions`, `productCategoryOptions`, and `productSubcategoryOptions` still derive from `availableProducts` (`src/Sales&Purchase/SalesOrderDashboard.jsx:1505-1554`). A failed global preload therefore empties those selectors even while dealer pages and text search work. Populate the choices from dealer-scoped pages or endpoint facets to remove the remaining dependency.

## Per-company lease coordinates worker and replica schedules

Each runner atomically acquires the fixed `sales-order-expiration` lease in the company database only when absent or expired (`crm_backend/cron/salesOrderExpiration.js:5-38`). MongoDB driver 6.18 returns the updated document directly; the compatibility fallback also accepts `{ value }`, while duplicate-key code 11000 is treated as an expected lease miss.

Release is owner-scoped and runs in `finally`; the five-minute expiry permits recovery after process death (`crm_backend/cron/salesOrderExpiration.js:41-49`, `101-111`). If work exceeds the lease duration, the existing status, expiry-date, and `isExpired` predicates still prevent a second writer from changing the order or appending duplicate history (`crm_backend/cron/salesOrderExpiration.js:64-99`). The distributed lease resolves the per-worker/replica scan finding without a new blocker/high failure mode.
