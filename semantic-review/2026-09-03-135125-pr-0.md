# Sales Order promise-stage provenance on Dealer Invoices

The change adds a Dealer Invoice line snapshot for the Sales Order’s `requiredSequentialStageRatePercentage`, assigning it from the matched Sales Order line for linked invoices and clearing it for standalone invoices. Create, edit, and saved-detail paths display the snapshot separately while invoice-selected levels recalculate only the live required stage. Exact line IDs protect duplicate Sales Order products, and the source value is excluded from discount stages and totals. The legacy display fallback still presents an invoice-derived live value as Sales Order provenance when no source snapshot exists.

Watch for: **confirmed** legacy linked invoices without the new snapshot can display `requiredSequentialStageRatePercentage` as the “Sales Order additional promise stage,” even though it was calculated from invoice stages and can differ from the original Sales Order stage.

**Verdict**: NEEDS_CHANGES

## High-level view

Linked lines are matched by `sourceSalesOrderLineId`; duplicate product lines cannot fall back to product identity. Canonicalization copies the source stage from that exact line and ignores client provenance, while standalone canonicalization always writes `null`.

The schema stores the snapshot independently. Frontend level changes and backend/model recalculation update only `requiredSequentialStageRatePercentage`, and financial calculations do not consume the source field.

Create hydration records the Sales Order value, while edit and detail paths read the persisted invoice value. **Confirmed:** when that field is absent on a legacy linked invoice with no positive invoice level, both views substitute the live invoice-required stage and label it as Sales Order provenance.

## Legacy invoices fabricate Sales Order provenance from the live invoice stage

`getSourceSalesOrderPromiseStage` falls back from a missing `sourceSalesOrderRequiredSequentialStageRatePercentage` to `requiredSequentialStageRatePercentage` (`src/Sales&Purchase/DealerInvoice.jsx:168-170`). The form enables this for linked lines with no selected levels (`src/Sales&Purchase/DealerInvoice.jsx:3995-4000`), and saved details enable it when the preview has no positive level stage (`src/Sales&Purchase/DealerInvoice.jsx:5717-5722`). This is **confirmed** to violate the legacy requirement: the fallback is recalculated from the invoice’s current stages (`src/Sales&Purchase/DealerInvoice.jsx:177-250`; `crm_backend/models/DealerInvoice.js:443-495`), not recovered from a historical Sales Order snapshot.

The value can differ when the original Sales Order used a selected level, because linked invoice hydration deliberately starts with no invoice-owned levels. Such a legacy invoice can show the invoice’s larger remaining required stage under the label “Sales Order additional promise stage.” Missing snapshots must remain `Not recorded`; any backfill must use an authoritative Sales Order line rather than the live invoice field.
