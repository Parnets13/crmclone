DealerInvoice canonicalization now converts normalized manual level rates into a real `Map` immediately before items cross into the Mongoose schema. The linked and standalone boundaries cover create, item-bearing draft update/sync, and linked approval replay without changing policy checks or JSON response shapes. Focused runtime checks reproduce the old null-prototype cast failure and validate the corrected boundary with zero, decimal, and custom-name rates. ## High-level view

Both canonical return paths convert the complete normalized entry set rather than rebuilding rates from selected stages. Explicit zero rates, decimal values, and custom level-name strings survive while mapping, cap, and actor-permission checks remain ahead of persistence.

The `Map` remains internal to persistence. Mongoose JSON serialization, preview normalization, and history normalization all expose `manualDiscountLevels` as the existing keyed JSON object; Mongoose still rejects unsafe map keys at schema casting.

## One schema-safe boundary for linked and standalone canonicalization

`normalizeRateMap` returns a null-prototype object that Mongoose 8.18.2 rejects for a `Map` schema path; focused model validation reproduced `Cast to Map failed`. Converting `Object.entries(manualDiscountLevels)` into a `Map` at both return sites produces the declared `DealerInvoice.items[].manualDiscountLevels` runtime type and validates successfully.

The conversion follows level lookup, configured-rate bounds, combined and master cap enforcement, actor-level authorization, and sequential calculation, so it does not bypass policy validation. It converts every normalized entry, preserving an explicit `0` instead of falling back to a configured rate during replay and retaining custom names such as `Custom / Tier Ω` with their numeric values.

Mongoose continues to reject prototype-sensitive and update-path keys such as `__proto__`, `constructor`, dotted names, and dollar-prefixed names. The fix therefore does not weaken the schema trust boundary or move dynamic keys back onto an ordinary object.

## Create, update/sync, and linked approval share the corrected item type

Create canonicalizes before constructing and saving `DealerInvoice`. Draft update runs the same helper whenever `items` is present—the synchronization path—and assigns the result before saving. Linked approval converts persisted subdocuments to objects, replays them against the Sales Order snapshot and selecting actor, replaces `invoice.items`, and saves in its transaction.

These are the helper's only three production call sites, and every call reaches a linked or standalone return now emitting a `Map`. Approval remains compatible with existing persisted maps because `normalizeRateMap` accepts `Map` input before reconversion.

## Preview and history retain object-shaped rate maps

Preview still emits its normalized rate object directly. Mongoose document JSON serialization flattens persisted maps for create, update, fetch, and approval responses, while discount history explicitly normalizes and spreads the persisted value. A focused serialization check produced the same object payload in all three cases, including a zero and decimal custom-level rate; internal `toObject()` output remains a `Map` for approval replay.
