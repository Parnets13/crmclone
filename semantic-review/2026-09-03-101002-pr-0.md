# Rolling absence review, repeat face punches, and resilient invoice search

The attendance review window becomes a rolling 15-day policy, while face attendance derives each punch from today’s sessions and rechecks state before writing. Invoice search now tolerates missing and non-string values and makes Draft searchable. The date boundary, repeated face sessions, cancellation guard, source attribution, and active invoice filtering align, but expired unresolved absences can still receive different outcomes depending on whether cron or the review list handles them first.

**Watch for:** **confirmed** — cron can convert an expired `none`/`null` absence to `auto_paid`, while the new list endpoint converts the same row to Unexcused Unpaid; settlement is order-dependent.

**Verdict**: NEEDS_CHANGES

## High-level view

On September 2, August 18 remains reviewable and August 17 or earlier is expired. Pending-list bounds, manual actions, and the serialized record deadline use that cutoff, with the deadline covering the final eligible IST day.

**Confirmed:** expired settlement diverges across entry points. The list settles `pending`, `none`, and `null` rows as Unexcused Unpaid with the configured multiplier, but cron initially settles only `pending`; expired `none`/`null` rows can enter free paid-leave classification first.

Face attendance reads `/attendance/today` before verification and after a match, selecting Punch Out only for an open session. Both face routes store `source: "face"`, and modal teardown blocks detector and delayed-success callbacks after cancellation.

Invoice search normalizes primitives, arrays, and known object fields. Missing or non-string invoice, dealer, customer-name, and sales-order values cannot fail on string methods, and Draft contributes the searchable literal `DRAFT`.

## Expired unresolved absences have an order-dependent paid/unpaid result

**Confirmed:** the new list request changes every expired Absent row with `pending`, `none`, or `null` review status to Unexcused Unpaid and stores the normalized configured multiplier. Cron’s first settlement query covers only `pending`; its later query sends expired `none`/`null` rows through ordinary classification, where remaining monthly quota changes a row to `auto_paid` before the catch-up unexcused update.

On September 2, an August 17 `none` row becomes Unexcused Unpaid if `/absent-review` runs first, or Paid Leave if cron runs first. Include `none` and `null` in cron’s expired settlement path, or exclude expired rows from free-leave classification, so all expired unresolved states receive the configured unpaid multiplier.

## September 2 boundary and record deadlines

The policy subtracts 15 calendar days from current IST midnight. On September 2 this yields August 18 00:00 IST; list and action queries accept `>=` August 18, while settlement expires dates `<` August 18.

For an August 18 record stored at IST midnight, `getAbsentReviewDeadline` returns September 2 23:59:59.999 IST, matching the final day accepted by actions. The simulation checks August 18 inclusion, August 17 exclusion, that deadline, and month rollover.

## Session-driven Face In / Face Out lifecycle

Today’s `sessions` select Face In when none is open and Face Out for an in-without-out. Closing the first session makes the refreshed state select Face In again; the backend appends a second session, after which Face Out is selected, supporting IN/OUT/IN/OUT without legacy top-level punch fields.

State is fetched before the camera opens and after a match; an action change rejects submission and requires fresh verification. Both punch requests send boolean `true`, and both backend branches store `faceVerified: true` and `source: "face"`.

After asynchronous detection, the component-active guard runs before scheduling attendance. Unmount marks it inactive, stops auto-scan, clears scan and success timers, and prevents the matched callback from submitting; accepted matches disable controls while the callback is pending.

## Null-safe active invoice search and Draft discovery

The filter no longer calls `.toLowerCase()` on payload fields. `normalizeSearchText` maps nullish values to empty text, stringifies primitives, flattens arrays, and extracts known object display fields before matching invoice number, dealer name or populated dealer, customer name, and sales-order number or populated sales order.

Draft rows contribute `DRAFT` when `isDraft` is true or status is `Draft`, so “draft” matches case-insensitively even without an invoice number.
