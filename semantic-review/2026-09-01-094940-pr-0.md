# Confirmed discount ownership flow after final fixes

The current implementation exposes configured mapping-defined discount names in User Management for every role, limits current-policy Sales Orders to Direct and Dealer Extra, preserves promise as non-pricing guidance, and retains persisted stages for legacy amount replay. Linked invoice creation and edit authorize selected levels against the acting creator/editor while keeping Sales Order terms locked and enforcing configured caps; the Sales Executive cap gates now run only for positive applicable stages. Approval, however, changes the authorization principal while replaying an otherwise valid linked draft. Watch for: **confirmed (medium)** a linked draft created or edited by a user who owns its selected levels cannot be approved by an approver who lacks those same level assignments.

**Verdict**: NEEDS_CHANGES

## High-level view

Current-policy Sales Orders execute only server-resolved Direct and Dealer Extra stages. Promise changes update guidance metadata without changing amounts, while quantity or price edits replay the persisted ordered stages rather than silently moving legacy orders to current policy.

Linked invoices inherit Direct, Dealer Extra, GST, promise, and caps from the Sales Order and allow the current creator/editor to choose assigned level stages. Approval rebuilds source-owned values but also re-authorizes persisted level choices against the approver, coupling approval permission to discount-level ownership.

User Management accepts both standard and mapping-defined names for every role, including Super Admin. Empty assignments intentionally remain no-access assignments.

The Sales Executive preview and request paths require the master cap only when a positive discount stage exists and the combined cap only when a positive level stage exists.

## Linked invoice approval replaces the selecting actor with the approver

This is **confirmed (medium)** in `crm_backend/controllers/dealerInvoiceController.js:215-229` and `crm_backend/controllers/dealerInvoiceController.js:1997-2005`. Creation and edit pass the current creator/editor into `canonicalizeInvoiceItems`, which loads that actor’s live `allowedDiscountLevels`; the shared policy validator rejects every positive level stage absent from that set. During linked-draft approval, the same canonicalizer receives `req.user._id`, so the actor becomes the approver rather than the user whose valid selection is persisted in the draft.

A creator assigned `Executive Discount` can save a valid linked draft, but an invoice approver without `Executive Discount` receives `DISCOUNT_LEVEL_NOT_ALLOWED` and cannot approve it. The approval route already has a separate invoice-approval permission, so requiring duplicate level ownership violates the ownership split between selection and approval. Approval should continue replaying and cap-checking source-owned values, but validate persisted level authorization against the draft’s selecting actor/snapshot; only a changed selection should be authorized against the actor making that change.

</details>
