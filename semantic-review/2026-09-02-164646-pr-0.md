# Per-product notes across the GRN lifecycle

The change adds an optional note to each GRN product line and carries it through draft creation, edit, inspection, and supplier invoicing. Notes are normalized to trimmed strings of at most 500 characters on create and update, with the frontend enforcing the same input ceiling. Edit loading retrieves every attached PO directly so completed POs still provide the line data needed for reconciliation. No concrete blocker remains in the scoped lifecycle.

Watch for: No blocking concerns found in the scoped changes.

**Verdict**: APPROVED

## High-level view

Each product row owns its note in `formData.items`; the GRN item schema persists it, and detail responses restore it for editing and View Details.

PO selection rebuilds rows from selected PO lines. Notes are restored only when product, unit price, direct discount, and reference floating discount all match, preventing transfer between same-product lines with different commercial terms.

Inspection and supplier invoice creation update existing GRN item subdocuments rather than replacing the item array, so notes remain attached through both lifecycle transitions.

## Draft restoration and PO reconciliation identity

Draft edit deduplicates attached PO IDs, loads each through `getPurchaseOrder`, and rejects responses without `data.lines`. The service and purchase-order detail endpoint provide the expected `{ success, data }` shape with populated warehouse and product references, avoiding a new object-shape runtime failure.

Persisted direct and floating discounts are restored into the aliases used by reconciliation. The product/price/direct-discount/reference-floating key keeps a note on its exact merged commercial line; a same-product row with different pricing or discounts cannot inherit it.

## Normalization and downstream preservation

The client caps input at 500 characters, while both create and update trim and cap submitted strings before schema validation; non-string API values become empty notes. Inspection saves the loaded GRN without reconstructing items. Supplier invoicing spreads GRN items during frontend discount calculation, then writes `supplierCostPerUnit` and invoice metadata onto existing backend subdocuments, leaving remarks unchanged.

Backend syntax checks passed for `models/GRN.js` and `controllers/grnController.js`; Babel parsed `GRNEntryModule.jsx`; and `git diff --check` passed in both repositories. Targeted ESLint reports four existing unused-variable errors and one existing hook-dependency warning on unchanged lines, with no failure introduced by this change.
