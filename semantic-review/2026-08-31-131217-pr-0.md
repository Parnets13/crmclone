# Stock Arrived lifecycle synchronization after follow-up fixes

The follow-up fixes now recalculate submitted product edits, refresh reopened expiry state, protect the Stock Arrived predicate from expiry-filter overrides, and count only explicit readiness transitions. Terminal orders render stock as N/A, while a non-terminal `Pending` order separately shows when stock is ready. Two API-level integrity gaps remain: generic updates accept some client-authored lifecycle fields, and an empty product array is classified as fully ready.

Watch for: **confirmed (medium)** generic updates can persist client-authored aggregate/compatibility stock state and, on an unrefreshed repricing/status path, line stock state; **confirmed (medium)** removing every line makes an out-of-stock `Pending` order enter Stock Arrived as a zero-product ready order.

**Verdict**: NEEDS_CHANGES

## High-level view

**Confirmed (medium):** the dashboard omits line stock fields and the normal merge preserves server values, but the generic API does not remove order-level lifecycle fields. The repricing canonicalizer also starts from the submitted line, allowing requests outside the dashboard to author stock state when the resulting status skips refresh.

**Confirmed (medium):** readiness uses equality between available and total lines without requiring a nonzero total. Since updates accept an empty products array, zero available out of zero becomes `ready` and satisfies the Stock Arrived predicate.

## Generic updates retain client control over stock lifecycle state

This is **confirmed (medium)** in `salesOrderController.js:2140-2799`. The handler does not strip `orderStockStatus`, `stockAvailable`, or `stockAvailableNotifiedAt` before `findByIdAndUpdate`. Its synchronization branch only overwrites `stockAvailable` for a non-Pending/expired result or when the previously loaded order was already out of stock and ready; a `Pending` non-ready request can retain submitted `stockAvailable: true`, and a products-free request can replace `orderStockStatus` without triggering refresh.

`mergeNonFinancialProductUpdates` restores server-owned line fields, but `canonicalizeSalesOrderProducts` begins with `...submittedItem` and does not overwrite `stockStatus`, `availableQuantity`, `stockArrivedAt`, or `stockCheckedAt`. Refresh repairs these only when the resulting status is `Pending`, `Confirmed`, or `Processing`; repricing while moving an editable order to another schema-valid status such as `In Transit` persists submitted line stock values. Strip lifecycle fields before every product branch and synchronize from final status, expiry, out-of-stock state, and refreshed products.

## Empty product sets become ready orders

This is **confirmed (medium)** in `salesOrderController.js:2168-2175`, `2794-2802`, and `stockArrivalService.js:305-318`. The endpoint accepts `products: []`, and the schema has no nonempty-array validator. The forced refresh evaluates `availableCount === order.products.length` as `0 === 0`, writes `overallStatus: 'ready'`, and sets `stockAvailable` for a `Pending`, non-expired, out-of-stock order.

The zero-line order then matches both Stock Arrived queries and displays `Stock Ready!`. Reject empty products on create/update and defensively define zero lines as non-ready.
