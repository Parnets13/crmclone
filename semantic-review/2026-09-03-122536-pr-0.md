# Dealer-extra previews and sequential Sales Order promises

The change refreshes create-mode dealer extras after complete-info arrives, adds reducing-balance promise-stage editing, exposes all configured levels, and expands master-cap remainder reporting. Promise and cap inverses produce the required results, while canonical Sales Order totals remain direct plus server-resolved dealer extra. Backend complete-info supplies `targetId`, and ordinary edits replay persisted snapshots. The stale-response guard still uses values captured by the request's render, allowing old responses to overwrite current payment state or reprice a same-dealer edit.

Watch for: **confirmed** stale DealerInfoPanel completions can pass the new guard, overwrite current dealer payment state, and reapply dealer extras to an edit snapshot when the request captured add mode.

**Verdict**: NEEDS_CHANGES

## High-level view

The callback validates a response against render-scoped `formData.dealer` and gates repricing with render-scoped `modalType`. An out-of-order request therefore compares against the dealer and mode that launched it, not the live form, leaving dealer switches and add-to-edit transitions unsafe.

## Render-scoped checks do not reject out-of-order complete-info

The added handler compares `responseDealerId` with `formData.dealer` and checks `modalType !== 'edit'` (`SalesOrderDashboard.jsx:1846-1859`). This is **confirmed** ineffective for stale requests because `DealerInfoPanel` invokes the parent callback captured by the render that launched `loadDealerInfo` (`DealerInfoPanel.jsx:13-46`). A dealer-A request completing after a switch to dealer B still sees A in its callback, passes the guard, and writes A into `paymentStatusRef` and `paymentStatus` (`SalesOrderDashboard.jsx:1852-1853`). The functional dealer check protects line discounts in the A-to-B case, but save gating and displayed payment state remain stale until another response replaces them.

If an add-mode request completes after an edit for the same dealer opens, the callback also retains add mode and the functional dealer check passes, recalculating persisted lines with current dealer extras (`SalesOrderDashboard.jsx:1858-1867`). Sequence or cancel requests and compare against current dealer/mode refs before parent state updates, including credit-history completion.
