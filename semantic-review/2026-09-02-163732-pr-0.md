# Per-product GRN notes with discount-aware preservation

The change adds normalized per-item GRN notes, exposes them in create/edit and View Details, and preserves them while selected POs are re-merged by product, price, direct discount, and reference floating discount. Draft restore reconstructs the two discount aliases from persisted `purchaseDiscount` fields before matching. The Draft edit PO loader leaves the primary PO without `lines`, so selection changes can fail before note preservation runs.

Watch for: **confirmed (P1)** Draft edit PO selection/deselection can throw on the line-less primary PO, preventing notes from being preserved for unchanged merge identities.

**Verdict**: NEEDS_CHANGES

## High-level view

PO toggles rebuild all line groups and then copy a note only from an exact product/price/direct-discount/reference-floating match. Draft edit obtains its primary PO from a populated GRN reference that omits `lines`; retaining that PO during a toggle crashes the rebuild.

## Draft edit cannot rebuild identities while the primary PO remains selected

This is **confirmed (P1)**. Draft edit asks `getApprovedPOs('')` for full PO data (`GRNEntryModule.jsx:572`), but the backend removes every PO already used as a GRN primary from that response (`grnController.js:1080-1086`). The fallback GRN lookup populates only PO metadata and not `lines` (`grnController.js:798-800`), so the primary entry placed into `selectedPO` at `GRNEntryModule.jsx:576-585` has no line array.

`handlePOSelect` unconditionally executes `selectedPo.lines.forEach` for every PO that remains selected (`GRNEntryModule.jsx:211-213`). Adding another PO or deselecting a non-primary PO therefore throws while the line-less primary remains in `updated`; the new exact-identity note copy at `GRNEntryModule.jsx:276-287` is never reached. Load the edit PO identities through an endpoint that includes their populated lines, or have `getApprovedPOs` explicitly include the current Draft's PO IDs, before rebuilding and preserving notes.

</details>
